# Absences (Phase 2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the user record vacation, sickness and public holidays against freely defined absence types, and make those days count correctly toward the work-time balance.

**Architecture:** Two new synced Drift tables — `AbsenceTypes` (user-defined, each with a paid flag) and `Absences` (one row per calendar day, carrying a portion of `fullDay` / `halfDay` / `range`). Both follow the established per-row event-log pattern. The pure `balance_calculations.dart` module gains absence handling: a paid absence credits time toward the day, an unpaid one reduces the day's target, and `AppSettings.absenceTrackingEnabled` — the column phase 1 already shipped — switches whether work days without any booking count as a deficit. Recording happens through a third segment on the main screen beside Timer and Manual; the resulting rows appear in the entries list where they can be deleted.

**Tech Stack:** Flutter, Riverpod (plain providers — see Global Constraints), Drift, `intl`.

**Spec:** `docs/superpowers/specs/2026-09-02-worktime-balance-dashboard-design.md` — sections 2 (`AbsenceTypes`, `Absences`), 3 (calculation), 4 (settings UI), 5 (main-screen UI), and the phase 2 row of section 8. Phase 3's dashboard blocks are out of scope.

```dart
import 'package:drift/drift.dart';

/// A user-defined kind of absence — vacation, sickness, a public holiday,
/// unpaid leave. Nothing is hard-coded: Hickory is used internationally
/// and against different employment contracts, so the same reasoning that
/// keeps labour law out of BreakRuleTiers keeps absence kinds out of here.
///
/// [paid] decides how a day carrying this absence is scored. A paid
/// absence credits time toward the day's target; an unpaid one reduces the
/// target instead. Both leave a full day neutral in the balance, but the
/// reported target differs — which is the whole point of the flag.
///
/// Synced across the user's own devices via the event log, like every
/// other entity. See
/// docs/superpowers/specs/2026-09-02-worktime-balance-dashboard-design.md.
@DataClassName('AbsenceType')
class AbsenceTypes extends Table {
  TextColumn get id => text()();
  TextColumn get name => text()();
  BoolColumn get paid => boolean()();
  // Display order in Settings and in the recording form. Ties are broken
  // by name, so a fresh set of types created in one batch still lists
  // predictably.
  IntColumn get sortOrder => integer()();
  TextColumn get deviceId => text()();
  DateTimeColumn get createdAt => dateTime()();
  DateTimeColumn get updatedAt => dateTime()();

  @override
  Set<Column> get primaryKey => {id};
}
```

Create `lib/data/drift/daos/absence_types_dao.dart`:

```dart
import 'package:drift/drift.dart';
import 'package:uuid/uuid.dart';

import '../database.dart';
import '../tables/absence_types_table.dart';

part 'absence_types_dao.g.dart';

@DriftAccessor(tables: [AbsenceTypes])
class AbsenceTypesDao extends DatabaseAccessor<AppDatabase> with _$AbsenceTypesDaoMixin {
  AbsenceTypesDao(super.db);

  static const _uuid = Uuid();

  Stream<List<AbsenceType>> watchAllTypes() {
    return (select(absenceTypes)
          ..orderBy([
            (t) => OrderingTerm.asc(t.sortOrder),
            (t) => OrderingTerm.asc(t.name),
          ]))
        .watch();
  }

  Future<List<AbsenceType>> getAllTypes() {
    return (select(absenceTypes)
          ..orderBy([
            (t) => OrderingTerm.asc(t.sortOrder),
            (t) => OrderingTerm.asc(t.name),
          ]))
        .get();
  }

  Future<AbsenceType> createType({
    required String deviceId,
    required String name,
    required bool paid,
    required int sortOrder,
  }) async {
    final now = DateTime.now().toUtc();
    final id = _uuid.v4();
    await into(absenceTypes).insert(
      AbsenceTypesCompanion.insert(
        id: id,
        name: name,
        paid: paid,
        sortOrder: sortOrder,
        deviceId: deviceId,
        createdAt: now,
        updatedAt: now,
      ),
    );
    return (select(absenceTypes)..where((t) => t.id.equals(id))).getSingle();
  }

  /// Updates only the fields passed in; a null parameter leaves its column
  /// alone. Always bumps [updatedAt], because the sync log orders events by
  /// it — an edit that kept the old timestamp could lose to the row it
  /// replaced.
  Future<AbsenceType> updateType(
    String id, {
    String? name,
    bool? paid,
    int? sortOrder,
  }) async {
    await (update(absenceTypes)..where((t) => t.id.equals(id))).write(
      AbsenceTypesCompanion(
        name: name == null ? const Value.absent() : Value(name),
        paid: paid == null ? const Value.absent() : Value(paid),
        sortOrder: sortOrder == null ? const Value.absent() : Value(sortOrder),
        updatedAt: Value(DateTime.now().toUtc()),
      ),
    );
    return (select(absenceTypes)..where((t) => t.id.equals(id))).getSingle();
  }

  Future<void> deleteType(String id) {
    return (delete(absenceTypes)..where((t) => t.id.equals(id))).go();
  }
}
```

```dart
import 'package:drift/drift.dart';

/// The three shapes an absence can take. Stored as text rather than a
/// drift enum so an older peer ingesting a value it does not know reads a
/// harmless string instead of failing to decode the row.
const absencePortionFullDay = 'fullDay';
const absencePortionHalfDay = 'halfDay';
const absencePortionRange = 'range';

/// One day of absence: a vacation day, a sick day, a two-hour doctor's
/// appointment. Always **one row per calendar day** — a fortnight of
/// vacation entered once in the form becomes ten rows, skipping days whose
/// target is zero. That keeps the calculation a per-day lookup and lets a
/// single day be removed later; the cost is that a bulk entry is several
/// writes, which the write-through sync handles like any other batch.
///
/// [portion] is `fullDay`, `halfDay` or `range`. The first two store **no
/// minute figure** — only the portion — so the credited time is derived
/// from the day's target when it is read. An absence therefore stays
/// correct if the target is changed afterwards. `range` is the exception:
/// it carries [startAt] and [endAt] because its length is its own, not the
/// day's.
///
/// Synced across the user's own devices via the event log, like every
/// other entity. See
/// docs/superpowers/specs/2026-09-02-worktime-balance-dashboard-design.md.
@DataClassName('Absence')
class Absences extends Table {
  TextColumn get id => text()();
  // The calendar day this absence covers, stored as that day's *local*
  // midnight — the same key totalsByDay groups worked time by, so the two
  // line up without conversion.
  DateTimeColumn get date => dateTime()();
  // References AbsenceTypes.id. Deliberately no foreign key: the synced
  // tables carry none, so a row can outlive a peer's ordering of events.
  // Settings refuses to delete a type that is still referenced.
  TextColumn get absenceTypeId => text()();
  TextColumn get portion => text()();
  // UTC, set only when portion == absencePortionRange.
  DateTimeColumn get startAt => dateTime().nullable()();
  DateTimeColumn get endAt => dateTime().nullable()();
  TextColumn get note => text().nullable()();
  TextColumn get deviceId => text()();
  DateTimeColumn get createdAt => dateTime()();
  DateTimeColumn get updatedAt => dateTime()();

  @override
  Set<Column> get primaryKey => {id};
}
```

```dart
import 'package:drift/drift.dart';
import 'package:uuid/uuid.dart';

import '../database.dart';
import '../tables/absences_table.dart';

part 'absences_dao.g.dart';

@DriftAccessor(tables: [Absences])
class AbsencesDao extends DatabaseAccessor<AppDatabase> with _$AbsencesDaoMixin {
  AbsencesDao(super.db);

  static const _uuid = Uuid();

  Stream<List<Absence>> watchAllAbsences() {
    return (select(absences)..orderBy([(a) => OrderingTerm.asc(a.date)])).watch();
  }

  Future<Absence> createAbsence({
    required String deviceId,
    required DateTime date,
    required String absenceTypeId,
    required String portion,
    DateTime? startAt,
    DateTime? endAt,
    String? note,
  }) async {
    final now = DateTime.now().toUtc();
    final id = _uuid.v4();
    await into(absences).insert(
      AbsencesCompanion.insert(
        id: id,
        date: date,
        absenceTypeId: absenceTypeId,
        portion: portion,
        startAt: Value(startAt),
        endAt: Value(endAt),
        note: Value(note),
        deviceId: deviceId,
        createdAt: now,
        updatedAt: now,
      ),
    );
    return (select(absences)..where((a) => a.id.equals(id))).getSingle();
  }

  Future<void> deleteAbsence(String id) {
    return (delete(absences)..where((a) => a.id.equals(id))).go();
  }

  /// How many absence rows still reference [absenceTypeId]. Settings uses
  /// this to refuse deleting a type that is in use, rather than leaving
  /// rows pointing at a type that no longer exists — the tables carry no
  /// foreign key, so nothing else would stop it.
  Future<int> countByType(String absenceTypeId) async {
    final count = absences.id.count();
    final query = selectOnly(absences)
      ..addColumns([count])
      ..where(absences.absenceTypeId.equals(absenceTypeId));
    return (await query.getSingle()).read(count) ?? 0;
  }
}
```

### Task 5: Absences in the balance calculation

**Files:**
- Modify: `lib/features/reports/balance_calculations.dart`
- Test: `test/features/reports/balance_calculations_test.dart`

**Interfaces:**
- Consumes: `Absence`, `AbsenceType` and the `absencePortion*` constants from Tasks 1-2.
- Produces: `int absenceMinutes(Absence absence, int dayTargetMinutes, List<TimeEntry> dayEntries)`; `DayBalance` gains `final Duration absenceCredit` (defaulting to `Duration.zero`) and `balance` becomes `worked + absenceCredit - target`; `dayBalances` gains `{List<Absence> absences = const [], Map<String, AbsenceType> absenceTypesById = const {}, DateTime? through}`.

**The semantics this task implements**, from spec §3:
- A **paid** absence credits time toward the day; an **unpaid** one reduces the day's target instead. Both leave a full day neutral, but the reported target differs.
- A full day is worth the day's target, a half day exactly half of it. Neither stores a minute figure, so both stay correct if the target changes later.
- A range is worth its own length **minus any overlap with tracked work** — an appointment also tracked as work must not count twice. Full and half days are deliberately **not** reduced by tracked work: someone who works on a vacation day should see that time as a plus.
- `absenceTrackingEnabled` decides which days enter the balance at all. **Off:** only days with at least one finished entry, and absences are ignored entirely — a day off cannot be recorded, so counting empty work days would manufacture a deficit. **On:** every work day in range, so a work day with neither entries nor an absence shows up as a deficit. That visibility is the feature's real payoff.

```dart
/// Entries grouped by the local day they start on — the same grouping
/// [totalsByDay] uses, so a range absence is compared against exactly the
/// entries that day's worked total was built from.
Map<DateTime, List<TimeEntry>> _entriesByDay(List<TimeEntry> entries) {
  final byDay = <DateTime, List<TimeEntry>>{};
  for (final entry in entries) {
    if (entry.endAt == null) continue;
    final local = entry.startAt.toLocal();
    final day = DateTime(local.year, local.month, local.day);
    byDay.putIfAbsent(day, () => []).add(entry);
  }
  return byDay;
}

/// Minutes between [from] and [to] already covered by tracked work.
/// Overlapping entries are merged first, so two entries covering the same
/// minute do not subtract it twice.
int _overlapMinutes(DateTime from, DateTime to, List<TimeEntry> dayEntries) {
  final spans = <(DateTime, DateTime)>[];
  for (final entry in dayEntries) {
    final end = entry.endAt;
    if (end == null) continue;
    final start = entry.startAt.isAfter(from) ? entry.startAt : from;
    final stop = end.isBefore(to) ? end : to;
    if (!stop.isAfter(start)) continue;
    spans.add((start, stop));
  }
  if (spans.isEmpty) return 0;
  spans.sort((a, b) => a.$1.compareTo(b.$1));

  var covered = Duration.zero;
  var currentStart = spans.first.$1;
  var currentEnd = spans.first.$2;
  for (final span in spans.skip(1)) {
    if (span.$1.isAfter(currentEnd)) {
      covered += currentEnd.difference(currentStart);
      currentStart = span.$1;
      currentEnd = span.$2;
      continue;
    }
    if (span.$2.isAfter(currentEnd)) currentEnd = span.$2;
  }
  return (covered + currentEnd.difference(currentStart)).inMinutes;
}

/// What one absence contributes on its day, in minutes.
///
/// A full day is worth the day's whole target and a half day exactly half
/// of it — neither stores a minute figure, so both stay correct if the
/// target is changed later. A range is worth its own length minus any
/// overlap with tracked work, so an appointment that was also tracked as
/// work cannot be counted twice. Full and half days are deliberately not
/// reduced by tracked work: someone who works on a vacation day should see
/// that time as a plus.
int absenceMinutes(
  Absence absence,
  int dayTargetMinutes,
  List<TimeEntry> dayEntries,
) {
  switch (absence.portion) {
    case absencePortionFullDay:
      return dayTargetMinutes;
    case absencePortionHalfDay:
      return dayTargetMinutes ~/ 2;
    case absencePortionRange:
      final from = absence.startAt;
      final to = absence.endAt;
      if (from == null || to == null || !to.isAfter(from)) return 0;
      final minutes =
          to.difference(from).inMinutes - _overlapMinutes(from, to, dayEntries);
      return minutes < 0 ? 0 : minutes;
    default:
      // A portion this version does not know, written by a newer peer.
      // Contributing nothing is the safe reading: it neither invents
      // credit nor removes target the user did not ask to remove.
      return 0;
  }
}
```

```dart
/// Per-day balances, ascending by day.
///
/// With absence tracking **off**, only days carrying at least one finished
/// entry are returned and [absences] is ignored entirely: a day off cannot
/// be recorded, so counting empty work days would manufacture a deficit.
///
/// With it **on**, every work day between the first known day and
/// [through] is returned, so a work day with neither entries nor an
/// absence shows up as a deficit — that visibility is the point of the
/// feature. Days that are neither a work day nor carry anything are still
/// skipped, so a weekend adds no rows.
///
/// [through] is the last day to enumerate, normally today. It only extends
/// the range; days before the first entry or absence are never invented,
/// because a balance cannot start before the user did.
List<DayBalance> dayBalances(
  List<TimeEntry> entries,
  AppSettingsRow settings, {
  List<Absence> absences = const [],
  Map<String, AbsenceType> absenceTypesById = const {},
  DateTime? through,
}) {
  final workedByDay = totalsByDay(entries);

  if (!settings.absenceTrackingEnabled) {
    final days = workedByDay.keys.toList()..sort();
    return [
      for (final day in days)
        DayBalance(
          day: day,
          worked: workedByDay[day]!,
          target: Duration(minutes: targetMinutesForWeekday(settings, day.weekday)),
        ),
    ];
  }

  final entriesByDay = _entriesByDay(entries);
  final absencesByDay = <DateTime, List<Absence>>{};
  for (final absence in absences) {
    final date = absence.date;
    final day = DateTime(date.year, date.month, date.day);
    absencesByDay.putIfAbsent(day, () => []).add(absence);
  }

  final known = <DateTime>{...workedByDay.keys, ...absencesByDay.keys};
  if (known.isEmpty) return const [];
  final first = known.reduce((a, b) => a.isBefore(b) ? a : b);
  var last = known.reduce((a, b) => a.isAfter(b) ? a : b);
  if (through != null && through.isAfter(last)) last = through;

  final result = <DayBalance>[];
  for (
    var day = first;
    !day.isAfter(last);
    day = DateTime(day.year, day.month, day.day + 1)
  ) {
    final worked = workedByDay[day] ?? Duration.zero;
    final dayAbsences = absencesByDay[day] ?? const <Absence>[];
    final target = targetMinutesForWeekday(settings, day.weekday);
    if (target == 0 && worked == Duration.zero && dayAbsences.isEmpty) continue;

    var paidMinutes = 0;
    var unpaidMinutes = 0;
    for (final absence in dayAbsences) {
      final type = absenceTypesById[absence.absenceTypeId];
      // An absence whose type cannot be resolved — deleted, or not loaded
      // yet — contributes nothing rather than being guessed at.
      if (type == null) continue;
      final minutes =
          absenceMinutes(absence, target, entriesByDay[day] ?? const []);
      if (type.paid) {
        paidMinutes += minutes;
      } else {
        unpaidMinutes += minutes;
      }
    }

    final effectiveTarget = target - unpaidMinutes;
    result.add(
      DayBalance(
        day: day,
        worked: worked,
        target: Duration(minutes: effectiveTarget < 0 ? 0 : effectiveTarget),
        absenceCredit: Duration(minutes: paidMinutes),
      ),
    );
  }
  return result;
}
```

```dart
/// creation would have every device create its own "Vacation" row, all of
/// which would then sync into a pile of duplicates; the standard set is
/// therefore an explicit button the user presses once, on one device.
class AbsenceTypesEditor extends ConsumerStatefulWidget {
  const AbsenceTypesEditor({super.key});

  @override
  ConsumerState<AbsenceTypesEditor> createState() => _AbsenceTypesEditorState();
}

class _AbsenceTypesEditorState extends ConsumerState<AbsenceTypesEditor>
    with SettingsWriteGuard {
  @override
  String saveErrorMessage(AppLocalizations l10n) => l10n.settingsAbsencesSaveError;

  Future<void> _setEnabled(bool enabled) {
    return guardedWrite(() async {
      final writes = await ref.read(syncedWritesProvider.future);
      await writes.updateAppSettings(absenceTrackingEnabled: enabled);
    });
  }

  Future<void> _addStandardTypes() {
    final l10n = AppLocalizations.of(context);
    // Named in the user's language at creation time: the name is user data
    // from here on, editable and synced like any other type they add.
    final standard = <(String, bool)>[
      (l10n.settingsAbsenceTypeDefaultVacation, true),
      (l10n.settingsAbsenceTypeDefaultSick, true),
      (l10n.settingsAbsenceTypeDefaultHoliday, true),
      (l10n.settingsAbsenceTypeDefaultUnpaid, false),
    ];
    return guardedWrite(() async {
      final deviceId = await ref.read(deviceIdProvider.future);
      final writes = await ref.read(syncedWritesProvider.future);
      for (final (index, entry) in standard.indexed) {
        await writes.createAbsenceType(
          deviceId: deviceId,
          name: entry.$1,
          paid: entry.$2,
          sortOrder: index,
        );
      }
    });
  }

  Future<void> _delete(AbsenceType type) async {
    final l10n = AppLocalizations.of(context);
    // The synced tables carry no foreign keys, so nothing below this line
    // would stop a delete from orphaning absence rows. Checked here, and
    // refused with the count rather than a bare "cannot delete".
    final inUse = await ref.read(appDatabaseProvider).absencesDao.countByType(type.id);
    if (inUse > 0) {
      if (mounted) showMessage(l10n.settingsAbsenceTypeInUse(inUse));
      return;
    }
    await guardedWrite(() async {
      final writes = await ref.read(syncedWritesProvider.future);
      await writes.deleteAbsenceType(type.id);
    });
  }

  Future<void> _edit(AbsenceType? existing) async {
    final result = await showDialog<({String name, bool paid})>(
      context: context,
      builder: (_) => _AbsenceTypeDialog(existing: existing),
    );
    if (result == null) return;
    await guardedWrite(() async {
      final writes = await ref.read(syncedWritesProvider.future);
      if (existing != null) {
        await writes.updateAbsenceType(existing.id, name: result.name, paid: result.paid);
        return;
      }
      final deviceId = await ref.read(deviceIdProvider.future);
      final types = ref.read(absenceTypesProvider).value ?? const <AbsenceType>[];
      // One past the highest existing order, not the list length: deleting
      // a type in the middle leaves a gap, and reusing the length would
      // then collide with a row that already has that value.
      final nextOrder = types.isEmpty
          ? 0
          : types.map((t) => t.sortOrder).reduce((a, b) => a > b ? a : b) + 1;
      await writes.createAbsenceType(
        deviceId: deviceId,
        name: result.name,
        paid: result.paid,
        sortOrder: nextOrder,
      );
    });
  }

  /// Moves [type] one place up or down. Spec section 2 lists reordering
  /// alongside add, rename and delete.
  Future<void> _move(AbsenceType type, int delta) {
    final types = [...?ref.read(absenceTypesProvider).value];
    final index = types.indexWhere((t) => t.id == type.id);
    final target = index + delta;
    if (index < 0 || target < 0 || target >= types.length) return Future.value();
    types.insert(target, types.removeAt(index));
    // Renumbered from zero rather than swapping the two rows' values: two
    // devices that each added a type while offline can produce duplicate
    // sortOrders, and swapping two equal values would silently do nothing.
    return guardedWrite(() async {
      final writes = await ref.read(syncedWritesProvider.future);
      for (final (position, moved) in types.indexed) {
        if (moved.sortOrder == position) continue;
        await writes.updateAbsenceType(moved.id, sortOrder: position);
      }
    });
  }

  @override
  Widget build(BuildContext context) {
    final l10n = AppLocalizations.of(context);
    final settings = ref.watch(appSettingsProvider).value;
    final types = ref.watch(absenceTypesProvider).value ?? const <AbsenceType>[];
    if (settings == null) return const Center(child: CircularProgressIndicator());

    return Column(
      crossAxisAlignment: CrossAxisAlignment.start,
      children: [
        SwitchListTile(
          contentPadding: EdgeInsets.zero,
          title: Text(l10n.settingsAbsencesEnabled),
          subtitle: Text(l10n.settingsAbsencesEnabledDescription),
          value: settings.absenceTrackingEnabled,
          onChanged: busy ? null : _setEnabled,
        ),
        const Divider(),
        const SizedBox(height: 8),
        Text(l10n.settingsAbsenceTypesTitle, style: Theme.of(context).textTheme.titleMedium),
        const SizedBox(height: 8),
        for (final type in types)
          ListTile(
            contentPadding: EdgeInsets.zero,
            title: Text(type.name),
            subtitle: Text(
              type.paid ? l10n.settingsAbsenceTypePaid : l10n.settingsAbsenceTypeUnpaid,
            ),
            trailing: Row(
              mainAxisSize: MainAxisSize.min,
              children: [
                IconButton(
                  key: ValueKey('moveAbsenceTypeUp-${type.id}'),
                  icon: const Icon(Icons.arrow_upward),
                  tooltip: l10n.settingsAbsenceTypeMoveUp,
                  onPressed:
                      busy || type == types.first ? null : () => _move(type, -1),
                ),
                IconButton(
                  key: ValueKey('moveAbsenceTypeDown-${type.id}'),
                  icon: const Icon(Icons.arrow_downward),
                  tooltip: l10n.settingsAbsenceTypeMoveDown,
                  onPressed:
                      busy || type == types.last ? null : () => _move(type, 1),

                IconButton(
                  key: ValueKey('editAbsenceType-${type.id}'),
                  icon: const Icon(Icons.edit_outlined),
                  tooltip: l10n.commonEdit,
                  onPressed: busy ? null : () => _edit(type),
                ),
                IconButton(
                  key: ValueKey('deleteAbsenceType-${type.id}'),
                  icon: const Icon(Icons.delete_outline),
                  tooltip: l10n.commonDelete,
                  onPressed: busy ? null : () => _delete(type),
                ),
              ],
            ),

        const SizedBox(height: 8),
        Row(
```

```dart
import '../../data/drift/database.dart';
import '../reports/balance_calculations.dart' show targetMinutesForWeekday;

/// The calendar days a bulk absence entry actually covers: every day from
/// [from] to [to] inclusive whose weekday has a target above zero.
///
/// Free days are skipped rather than recorded as absences, because an
/// absence on a day with no target would credit nothing and only add a row
/// the user then has to look at. A reversed span yields nothing rather
/// than throwing: the only caller is a pair of date pickers, and an empty
/// result is a state the form already has to report.
List<DateTime> absenceDaysBetween(
  DateTime from,
  DateTime to,
  AppSettingsRow settings,
) {
  final first = DateTime(from.year, from.month, from.day);
  final last = DateTime(to.year, to.month, to.day);
  if (last.isBefore(first)) return const [];

  final days = <DateTime>[];
  for (
    var day = first;
    !day.isAfter(last);
    day = DateTime(day.year, day.month, day.day + 1)
  ) {
    if (targetMinutesForWeekday(settings, day.weekday) > 0) days.add(day);
  }
  return days;
}
```

```dart
final workTimeBalanceProvider = Provider<AsyncValue<Duration>>((ref) {
  final entries = ref.watch(allEntriesProvider);
  final settings = ref.watch(appSettingsProvider);
  final absences = ref.watch(absencesProvider);

  if (entries is AsyncError<List<TimeEntry>>) {
    return AsyncValue.error(entries.error, entries.stackTrace);
  }
  if (settings is AsyncError<AppSettingsRow>) {
    return AsyncValue.error(settings.error, settings.stackTrace);
  }
  if (entries.isLoading || settings.isLoading) return const AsyncValue.loading();
  final entryList = entries.value;
  final settingsRow = settings.value;
  if (entryList == null || settingsRow == null) return const AsyncValue.loading();

  // Absences only matter, and only have to be waited for, while the
  // feature is on. With it off a failing absence stream must not take
  // down a balance that does not read absences at all.
  var absenceList = const <Absence>[];
  if (settingsRow.absenceTrackingEnabled) {
    if (absences is AsyncError<List<Absence>>) {
      return AsyncValue.error(absences.error, absences.stackTrace);
    }
    final loaded = absences.value;
    if (loaded == null) return const AsyncValue.loading();
    absenceList = loaded;
  }

  final now = DateTime.now();
  return AsyncValue.data(
    runningBalance(
      dayBalances(
        entryList,
        settingsRow,
        absences: absenceList,
        absenceTypesById: ref.watch(absenceTypesByIdProvider),
        // Enumerate up to today, so a work day that was neither booked
        // nor excused shows up as the deficit it is.
        through: DateTime(now.year, now.month, now.day),
      ),
      settingsRow,
      asOf: now,
```
